## 🧱 1-1. 技術スタック（pom.xml を読む）

[pom.xml](../pom.xml) の `<dependencies>` から、このアプリの「部品」が分かります。

| 依存 | 役割 | このアプリでの使われ方 |
| --- | --- | --- |
| `spring-boot-starter-web` | Spring MVC / 組込Tomcat | Controller・HTTP・セッション |
| `spring-boot-starter-data-jpa` | Spring Data JPA / Hibernate | DAO・Entity・DB アクセス |
| `spring-boot-starter-thymeleaf` | Thymeleaf | `templates/*.html` のレンダリング |
| `postgresql`（runtime） | JDBC ドライバ | PostgreSQL 接続 |
| `lombok`（optional） | ボイラープレート削減 | `@Data` `@NoArgsConstructor` 等 |
| `spring-boot-starter-test`（test） | JUnit5 / Mockito / MockMvc | `src/test` のテスト一式 |

```xml
<parent>

    <version>3.0.4</version>
</parent>
<properties>

</properties>
```

👉 **Spring Boot 3.0.4 / Java 17**。これが「土台のバージョン」。

## 🚀 1-2. 起動クラス `BlogApplication`

[BlogApplication.java](../src/main/java/blog/ex/BlogApplication.java) はたった14行ですが、全ての出発点です。

```java
@SpringBootApplication
public class BlogApplication {
    public static void main(String[] args) {
        SpringApplication.run(BlogApplication.class, args);
    }
}
```

### `@SpringBootApplication` が内包する3つのアノテーション

| 内包アノテーション | やること |
| --- | --- |
| `@SpringBootConfiguration` | このクラスを設定クラスとして扱う |
| `@EnableAutoConfiguration` | クラスパスの依存から自動設定（Tomcat起動・JPA設定など） |
| `@ComponentScan` | **このクラスのパッケージ（`blog.ex`）以下を走査** し、`@Controller`/`@Service`/`@Entity` 等を自動登録 |

👉 ポイントは `@ComponentScan` の起点が `blog.ex` であること。
　 だから Controller も Service も DAO も **`blog.ex` 配下に置く必要がある**（置き場所＝スキャン対象）。

## 🔁 1-4. 1リクエストの流れ（ブログ一覧表示を例に）

「ログイン後にブログ一覧を見る」処理を例に、層をまたぐ流れを追います。

```text
① ブラウザ: GET /user/blog/list
        │
        ▼
② BlogListController#getBlogListPage(Model)
        │   session.getAttribute("user") で UserEntity を取得 → userId
        ▼
③ BlogService#findAllBlogPost(userId)
        │   userId が null なら null、そうでなければ DAO へ委譲
        ▼
④ BlogDao#findByUserId(userId)   ← Spring Data JPA がSQLを自動生成
        │   SELECT * FROM blogs WHERE user_id = ?
        ▼
⑤ List<BlogEntity> がDBから返る
        │   model.addAttribute("blogList", blogList)
        ▼
⑥ "blog-list.html" を返す → Thymeleaf が HTML を生成 → ブラウザへ
```

👉 **上の層は下の層しか知らない**（Controller→Service→DAO→Entity）。
　 この一方向の依存が「レイヤードアーキテクチャ」の肝で、テストのしやすさにも直結します（[07](07_単体テスト解説_Service編.md)・[08](08_単体テスト解説_Controller編.md)）。

### 各層の責務を1行で

| 層 | クラス例 | 責務（やること） | やらないこと |
| --- | --- | --- | --- |
| Controller | `BlogListController` | HTTP・画面・セッション・モデル詰め | 業務判断・SQL |
| Service | `BlogService` | 業務判断（null判定・重複判定など） | HTTP・SQL文 |
| DAO | `BlogDao` | DBアクセス（CRUD） | 業務判断・画面 |
| Entity | `BlogEntity` | テーブル1行の「形」 | 動き（ロジック） |

## ⚙️ 1-5. DB / JPA 設定（application.properties）

[application.properties](../src/main/resources/application.properties)：

```properties
# DBの設定
spring.datasource.url=jdbc:postgresql://localhost:5433/blog_demo
spring.datasource.username=postgres
spring.datasource.password=123456

# jpaの設定
spring.jpa.properties.hibernate.dialect=org.hibernate.dialect.PostgreSQLDialect
spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true.
logging.level.org.hibernate.SQL=DEBUG
```

| 設定 | 意味 |
| --- | --- |
| `datasource.url` | 接続先。**ポート 5433** の `blog_demo` DB |
| `ddl-auto=update` | 起動時に Entity に合わせて **テーブルを自動生成/追従** |
| `show-sql=true` | 実行 SQL をログ出力（学習に便利） |
| `format_sql=true.` | SQL を整形（末尾の `.` はタイプミスだが致命的ではない） |

> ⚠️ `ddl-auto=update` は学習用には便利ですが、本番では `validate` などにして
> **スキーマ変更を手動管理** するのが定石です。
> パスワードを `.properties` に平文で書いている点も学習用ゆえの割り切りです。

## ✅ 1-6. まとめ

- 土台は **Spring Boot 3.0.4 / Java 17**、`web` + `data-jpa` + `thymeleaf` の3本柱。
- 起点は `@SpringBootApplication`。`blog.ex` 以下をコンポーネントスキャンする。
- 層は **Controller → Service → DAO → Entity** の一方向依存。
- 認証は **HttpSession**（Spring Security 不使用）。
- DB は PostgreSQL、`ddl-auto=update` でテーブル自動生成。
